Task: Build a production-grade Enterprise Form System for NASSAQ (not just UI)

Objective:
Implement a reusable, system-level Form Architecture that enforces:
- no-scroll UX (desktop)
- structured multi-step workflows
- consistent layout and behavior across all forms

This is NOT a UI improvement.
This is a Form Operating System.

--------------------------------------------------
1) HARD CONSTRAINTS (NON-NEGOTIABLE)
--------------------------------------------------

1. Desktop forms MUST have zero vertical scroll
2. Each step MUST fit entirely within viewport height
3. Max fields per step = 6–8 (strict rule)
4. If fields exceed limit → auto split into new step
5. Action buttons MUST always be visible (sticky)
6. Validation must NOT require scrolling to be seen

If any step violates these → it is considered a failure.

--------------------------------------------------
2) FORM ARCHITECTURE (MANDATORY)
--------------------------------------------------

Implement this structure:

FormContainer
 ├── Header
 ├── StepIndicator
 ├── FormStep (dynamic)
 │     ├── FormSection (1..n)
 │     │     ├── FormGrid
 │     │     │     ├── FormField
 │     │
 ├── StickyActionBar

All forms MUST use this structure.

--------------------------------------------------
3) COMPONENT CONTRACTS
--------------------------------------------------

Define and implement:

1. FormContainer
   - manages global state
   - controls steps
   - handles submission

2. FormStep
   - receives step config
   - enforces field limits
   - handles validation

3. FormSection
   - groups related fields
   - renders card layout

4. FormGrid
   - enforces layout:
     desktop → 2–3 columns
     tablet → 2 columns
     mobile → 1 column

5. StickyActionBar
   - always visible
   - handles navigation

6. StepIndicator
   - shows progress
   - tracks step state

7. FormField
   - unified input interface
   - supports validation + error display

--------------------------------------------------
4) LAYOUT ENGINE (IMPORTANT)
--------------------------------------------------

Implement layout rules programmatically:

- Detect viewport height
- Calculate max rows per step
- Prevent overflow

If overflow detected:
→ auto split into new step OR reorganize grid

Do NOT allow overflow-y scroll.

--------------------------------------------------
5) STATE MANAGEMENT RULES
--------------------------------------------------

- Centralized state (Zustand or equivalent)
- Persist data across steps
- No data loss on navigation
- Optional: draft persistence

--------------------------------------------------
6) VALIDATION ENGINE
--------------------------------------------------

- Validate per step
- Only validate visible fields
- Errors must be inline
- No global error blocking

--------------------------------------------------
7) UX RULES
--------------------------------------------------

- Always show:
  - step title
  - step context
- Always group fields into sections
- Never show long unstructured form
- Never hide required fields below viewport

--------------------------------------------------
8) RESPONSIVENESS RULES
--------------------------------------------------

Desktop:
- Strict no scroll

Tablet:
- minimal scroll allowed if unavoidable

Mobile:
- scroll allowed but optimized

--------------------------------------------------
9) APPLY TO THESE FLOWS FIRST
--------------------------------------------------

1. Create School
2. Teacher Registration
3. Student Creation

--------------------------------------------------
10) TESTING (MANDATORY)
--------------------------------------------------

For each form:

1. Desktop:
   - confirm no scroll exists
   - confirm all fields visible

2. Validation:
   - errors visible without scroll

3. Navigation:
   - no data loss

4. Edge cases:
   - long input values
   - missing fields
   - dynamic fields

--------------------------------------------------
11) OUTPUT REQUIRED
--------------------------------------------------

1. Component architecture
2. Layout engine explanation
3. Step splitting logic
4. How scroll was prevented
5. Before vs after UX
6. List of modified screens

--------------------------------------------------
12) CRITICAL RULE
--------------------------------------------------

If any form still requires scrolling on desktop:
→ implementation is considered FAILED
