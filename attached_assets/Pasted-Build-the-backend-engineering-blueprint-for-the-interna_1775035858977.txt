D) TASK 3 — EVENT FLOW
==================================================

Design the complete event flow of Product Intelligence Hub.

Goal:
Map exactly what happens after every important action in the system.

Create event-driven lifecycle flows for:

1. Issue Created
2. Issue Updated
3. Hakim Analysis Started
4. Hakim Analysis Completed
5. Duplicate Detected
6. Prompt Generated
7. Issue Assigned
8. Status Changed
9. SLA Warning Triggered
10. Issue Marked Done
11. Feedback Loop Sent
12. User Confirmed Resolved
13. User Rejected Resolution
14. Issue Reopened
15. Comment Added
16. Attachment Added

For each event, define:
- trigger
- preconditions
- business logic
- database writes
- activity log entry
- notifications if any
- permissions involved
- next state

Important lifecycle rules:

Issue lifecycle:
- New
- Under Review
- In Progress
- QA Validation
- Done
- Rejected
- User Feedback Confirmed

Required status logic:
- New → Under Review
- Under Review → In Progress
- In Progress → QA Validation
- QA Validation → Done
- Done → User Feedback Confirmed
- Done → Under Review (if user says issue not resolved)
- Any final closure requires Platform Admin

Feedback loop logic:
When issue becomes Done:
- send feedback request to issue creator:
  "تم حل المشكلة — هل تم حلها فعلاً؟"
- If user says Yes:
  - change status to User Feedback Confirmed
  - create activity log
- If user says No:
  - change status back to Under Review
  - create activity log
  - mark issue as reopened

Hakim AI event flow:
When issue is created:
- save issue in DB
- save submission metadata
- run Hakim analysis
- suggest title
- suggest priority
- check duplicates
- suggest responsible team
- store AI result
- create activity log entry

SLA event flow:
- calculate SLA based on priority
- track time elapsed
- flag issue if SLA exceeded
- expose SLA state in API responses
- show status-based progress %

Progress logic:
- New = 10%
- Under Review = 25%
- In Progress = 55%
- QA Validation = 80%
- Done = 100%
- User Feedback Confirmed = 100%
