# 🧠 NASSAQ – Attendance Metrics Investigation & Enforcement Prompt

## 🎯 Objective

هناك مشكلة واضحة في عرض مؤشرات الحضور داخل النظام:

* حضور المعلمين: **96%**
* حضور الطلاب: **92.5%**

وذلك بالرغم من عدم وجود أي بيانات حضور مخزنة في قاعدة البيانات.

---

## ❗ المطلوب

أريد تحقيقًا تقنيًا دقيقًا يوضح:

### 1) مصدر هذه القيم

تحقق بشكل صريح مما إذا كانت هذه القيم ناتجة عن:

* Mock Data داخل الـ frontend أو backend
* Hardcoded Default Values
* Fallback Logic عند عدم وجود بيانات
* Calculation Logic Bug

---

### 2) تتبع مكان توليد القيم

حدد بدقة:

* الملف (File)
* الدالة (Function)
* الكومبوننت (Component)
* أو الـ API Endpoint

الذي يقوم بإنتاج هذه القيم

---

### 3) تحليل منطق الحساب

* كيف يتم حساب نسبة الحضور؟
* ما هو الـ query المستخدم؟
* ماذا يحدث عندما تكون قاعدة البيانات فارغة؟

---

## 🚨 Critical Requirement (MANDATORY)

> ❗ يجب أن يتم عرض جميع بيانات الحضور بناءً على البيانات الفعلية داخل قاعدة البيانات فقط

### ❌ ممنوع تمامًا:

* استخدام Mock Data
* استخدام Default Values
* عرض أي نسبة بدون بيانات حقيقية

---

## ⚙️ Expected System Behavior (Correct Behavior)

### في حالة وجود بيانات:

* يتم حساب النسبة بناءً على:

  * عدد الحاضرين
  * إجمالي العدد
* ويتم عرض النسبة الفعلية

---

### في حالة عدم وجود بيانات:

يجب أن يقوم النظام بـ:

* عرض Empty State مثل:

  * "لا توجد بيانات حضور حتى الآن"
* أو عرض:

  * 0% بشكل صريح (إذا كان ذلك منطقيًا حسب التصميم)

---

### ❌ لا يجب إطلاقًا:

* عرض نسب عشوائية أو تقديرية
* أو أي قيمة غير مستندة إلى DB

---

## 🧩 4) المطلوب تنفيذه (Fix)

* إزالة أي Mock / Hardcoded / Fallback Logic
* تعديل الكود بحيث:

  * يعتمد فقط على DB Query
* إضافة شرط واضح:

```pseudo
if no attendance records:
    show empty state
else:
    calculate and display percentage
```

---

## 🗃️ 5) Logging Requirement

* تسجيل كل عملية حساب للحضور في قاعدة البيانات:

```json
{
  "action": "CALCULATE_ATTENDANCE",
  "entity": "attendance_metrics",
  "schoolId": "",
  "result": {
    "teachers": "",
    "students": ""
  },
  "dataSource": "database_only",
  "timestamp": ""
}
```

---

## 🔍 Final Output Required

أريد تقرير واضح يحتوي على:

* السبب الحقيقي لظهور هذه القيم
* مكان المشكلة في الكود
* هل هي Mock / Default / Bug
* ما الذي تم تعديله
* تأكيد أن النظام الآن يعتمد فقط على قاعدة البيانات

---

## 🔥 Final Rule

> أي رقم يظهر في النظام = يجب أن يكون له مصدر واضح داخل قاعدة البيانات
> إذا لم يوجد مصدر → لا يتم عرضه
