==================================================
B) VALIDATION RULES (STRICT ENFORCEMENT)
==================================================

Implement backend-level validation.

--------------------------------------------------
1) REQUIRED FIELDS VALIDATION
--------------------------------------------------

On issue creation:

MUST require:
- type
- employee_name
- account_type
- section
- page
- current_behavior
- expected_behavior

If missing:
→ reject request with validation error

--------------------------------------------------
2) EMPLOYEE NAME RULE
--------------------------------------------------

- employee_name is mandatory
- cannot be empty
- cannot be null
- must be at least 3 characters

--------------------------------------------------
3) ENUM VALIDATION
--------------------------------------------------

- All enums must be validated strictly
- Reject any value outside allowed enum set

--------------------------------------------------
4) STATUS TRANSITION VALIDATION
--------------------------------------------------

Allowed transitions ONLY:

new → under_review  
under_review → in_progress  
in_progress → qa_validation  
qa_validation → done  

done → user_feedback_confirmed  
done → under_review  

rejected → (no transition unless admin override)

--------------------------------------------------
5) FINAL STATUS RESTRICTION
--------------------------------------------------

Only Platform Admin can set:
- done
- rejected
- user_feedback_confirmed

Reject any request from non-admin.

--------------------------------------------------
6) PROMPT ACCESS VALIDATION
--------------------------------------------------

- Only Platform Admin can:
  - generate prompt
  - view prompt
  - copy prompt

Block all others.

--------------------------------------------------
7) ASSIGNMENT VALIDATION
--------------------------------------------------

- Only Platform Admin can assign issue
- Validate assigned_to exists
- Validate team enum

--------------------------------------------------
8) DUPLICATE HANDLING VALIDATION
--------------------------------------------------

- Prevent exact duplicate creation (optional rule)
- Flag duplicates via AI but do not block creation

--------------------------------------------------
9) ATTACHMENT VALIDATION
--------------------------------------------------

- Limit file size
- Allow only supported formats (image, video, pdf)
- Reject invalid uploads

--------------------------------------------------
10) DATE & TIME VALIDATION
--------------------------------------------------

Ensure:
- created_at always set
- created_date matches created_at
- created_time matches created_at
