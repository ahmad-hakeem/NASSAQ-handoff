# أمر تنفيذ: تنظيف البيانات الوهمية من المنصة بالكامل

## ضوابط إلزامية قبل البدء

* يُمنع تنفيذ أي حذف جماعي مباشر قبل إعداد قائمة واضحة بجميع مصادر البيانات الوهمية المكتشفة.
* يُمنع تصنيف أي بيانات على أنها وهمية فقط لأن الاسم يبدو غير مألوف أو غير احترافي، ما لم توجد مؤشرات إضافية تدعم ذلك.
* يُمنع أن يترتب على عملية التنظيف كسر أي واجهة أو تعطيل أي وظيفة داخل النظام.
* أي جزء من المنصة كان يعتمد على Demo Data يجب تحويله بعد التنظيف إلى **Empty State حقيقي** أو ربطه بمصدر بيانات فعلي.

## الهدف الرئيسي

تنفيذ عملية تنظيف شاملة لإزالة جميع البيانات الوهمية أو التجريبية أو المؤقتة من مختلف أجزاء المنصة، مع الحفاظ الكامل على:

* الكود الحقيقي
* البيانات الحقيقية
* إعدادات النظام
* الكيانات المرجعية اللازمة لتشغيل المنصة

## نطاق العمل

يشمل هذا العمل جميع المنصات والواجهات والمكونات داخل المشروع، بما في ذلك على الأقل:

* منصة مدير المنصة
* منصة مدير المدرسة
* منصة المعلم
* الصفحات والمكونات المشتركة
* الخدمات
* الـ APIs
* ملفات Seeds
* Fixtures
* Mock Data
* ملفات JSON
* أي بيانات محلية أو ثابتة مرتبطة بهذه المنصات

## ملاحظة حاسمة

مصدر البيانات الوهمية غير محسوم حاليًا، وقد تكون موجودة في:

* قاعدة البيانات فقط
* الواجهة الأمامية فقط
* أو في الاثنين معًا

لذلك يُمنع افتراض مصدر البيانات مسبقًا.
يجب البدء أولًا بتحقيق شامل لتحديد جميع مصادر البيانات الوهمية بدقة قبل تنفيذ أي حذف.

# المطلوب تنفيذه بالتسلسل

## أولًا: التحقيق الشامل قبل أي حذف

ابدأ بفحص واكتشاف أي بيانات وهمية أو تجريبية أو مزروعة مسبقًا داخل:

* قاعدة البيانات
* ملفات Seeding / Migration / Fixtures
* Mock APIs
* أي Hardcoded Arrays أو Objects داخل الفرونت إند
* Local Storage / Session Storage / Static State
* ملفات Constants / sampleData / demoData / fakeData
* البيانات الافتراضية المرتبطة بـ:

  * Dashboards
  * التقارير
  * الجداول
  * البطاقات
  * الحسابات
  * المستخدمين
  * المدارس
  * الفصول
  * الطلاب
  * المعلمين
  * الإشعارات
  * السجلات
  * الرسوم البيانية

## ثانيًا: تصنيف البيانات قبل اتخاذ أي إجراء

كل عنصر يتم العثور عليه يجب تصنيفه ضمن واحدة من الفئات التالية:

* بيانات وهمية مؤكدة
* بيانات تجريبية مرجحة
* بيانات حقيقية أو لا يجب المساس بها
* عناصر UI تعرض أرقامًا أو نصوصًا ثابتة من الفرونت إند وليست قادمة من قاعدة البيانات

## ثالثًا: معايير اعتبار البيانات مرشحة للتنظيف

يتم اعتبار البيانات مرشحة للتنظيف إذا انطبق عليها معيار واحد أو أكثر من المعايير التالية:

* احتواء الاسم أو القيمة على كلمات مثل:
  `test`, `demo`, `sample`, `mock`, `fake`, `default`, `temp`, `placeholder`
* وجود بريد إلكتروني أو رقم هاتف أو اسم مدرسة أو اسم مستخدم واضح أنه تجريبي
* وجود أرقام أو إحصاءات ثابتة مزروعة فقط لغرض العرض
* ظهور بيانات داخل الواجهة رغم أنها غير موجودة فعليًا في قاعدة البيانات
* وجود Seed Data أُنشئت فقط لتجربة الواجهة أو تسهيل التطوير
* وجود سجلات تعليمية أو أمنية أو تحليلية أو تقارير مصطنعة لأغراض العرض فقط

## رابعًا: الفصل بين مستويات التنظيف

يجب تنفيذ التنظيف على 3 مستويات مستقلة وواضحة:

1. تنظيف قاعدة البيانات من السجلات الوهمية
2. تنظيف الفرونت إند من أي Mock Data أو Hardcoded Demo Content
3. تنظيف طبقة الربط بين الفرونت إند والباك إند إذا كانت الواجهة تعتمد على Fallback أو Static Data عند غياب البيانات الحقيقية

## خامسًا: ممنوع الحذف الأعمى

قبل تنفيذ أي حذف، يجب الالتزام بما يلي:

* التمييز بدقة بين البيانات الوهمية وبين البيانات المرجعية اللازمة لتشغيل النظام
* عدم حذف:

  * الـ Admin الأساسي
  * الأدوار الأساسية
  * الصلاحيات
  * الإعدادات العامة
  * القيم المرجعية
  * أي Configuration مطلوب لتشغيل المنصة
* كذلك لا يتم حذف كلمات المرور أو الإيميلات المستخدمة في الحسابات التجريبية الرسمية الخاصة باختبار المنصة التالية:

### الحسابات التي يجب الإبقاء عليها

**مدير المنصة**
`admin@nassaq.com / Admin@123`

**مديرو المدارس**

* `principal1@nassaq.com`
* `principal2@nassaq.com`
* `principal3@nassaq.com`
* `principal4@nassaq.com`
* `principal5@nassaq.com`

**معلم**

* `teacher1@nor.edu.sa`

**طالب**

* `student1@nor.edu.sa`

**ولي أمر**

* `parent1@nor.edu.sa / Parent@123`

**كلمات المرور المعتمدة**

* `Principal@123`
* `Teacher@123`
* `Student@123`
* `Parent@123`

# المطلوب بعد انتهاء التنظيف

بعد إزالة البيانات الوهمية، يجب التأكد من الآتي:

* كل صفحة في المنصات الثلاث تعرض حالة صحيحة وسليمة
* في حال عدم وجود بيانات حقيقية، يتم عرض **Empty State حقيقي وواضح** بدلًا من أي بيانات تجريبية
* العدادات والجداول والكروت والرسوم البيانية والتقارير والسجلات والتنبيهات لا تعتمد على أرقام أو نصوص Hardcoded
* أي Dashboard أو Cards أو Charts لا تستمر في عرض أرقام ثابتة بعد التنظيف
* إصلاح أي Fallback وهمي موجود في الواجهة
* عدم ترك أي Placeholder Text ظاهر للمستخدم النهائي

---

# قاعدة تنفيذ مهمة: أصلح ولا تكتفِ بالحذف

إذا تبين أن بعض الواجهات تعتمد على بيانات وهمية حتى لا تنهار:

* لا تكتفِ بحذف البيانات فقط
* بل قم بتعديل الواجهة لتتعامل بشكل صحيح مع الحالات التالية:

  * عدم وجود بيانات
  * أول استخدام للنظام
  * حساب جديد بدون سجلات
  * مدرسة بدون معلمين أو طلاب
  * معلم بدون محتوى أو نشاط

المطلوب أن تصبح المنصة **Dynamic بالكامل** وتعمل بشكل طبيعي حتى في حالة عدم وجود أي بيانات تجريبية.

---

# التقرير النهائي المطلوب

في نهاية التنفيذ، أريد تقريرًا منظمًا وواضحًا يتضمن:

* ما الذي تم الإبقاء عليه ولماذا
* الملفات التي تم تعديلها
* الجداول أو الكيانات التي تم تنظيفها
* هل كانت هناك بيانات Hardcoded داخل الواجهات
* هل تم إصلاح الـ Empty States والـ Fallbacks
* أي مخاطر أو نقاط تحتاج إلى مراجعة بشرية

---

# قواعد التنفيذ العامة

* لا تفترض أن أي رقم ظاهر في الواجهة رقم حقيقي
* لا تفترض أن أي سجل في قاعدة البيانات يجب حذفه فقط لأنه قديم أو قليل الاستخدام
* لا تحذف البيانات الحقيقية أو الإعدادات الأساسية
* لا تترك أي جزء من المنصة يعتمد على Mock Content بعد انتهاء التنظيف
* إذا وُجد شك في أي عنصر، قم برفعه للمراجعة بدلًا من حذفه تلقائيًا

---

# أسلوب العمل المطلوب

نفّذ العمل بهذا الترتيب الصارم:

1. افحص أولًا
2. ثم نفّذ التنظيف بحذر
3. ثم أصلح الواجهات المتأثرة
4. ثم اختبر النتيجة
5. ثم قدّم التقرير النهائي

ويجب أن تتم المراجعة على مستوى **الكيانات المشتركة بين المنصات** وليس على مستوى الشاشة فقط.
فإذا كان المستخدم أو المدرسة أو التقرير أو التنبيه الوهمي يظهر في أكثر من منصة، فيجب إزالته من **المصدر الجذري** ومن جميع نقاط العرض المرتبطة به.
