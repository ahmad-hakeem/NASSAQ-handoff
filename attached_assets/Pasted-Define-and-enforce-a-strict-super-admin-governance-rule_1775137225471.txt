Define and enforce a strict super-admin governance rule across the entire system, with special emphasis on the "Product Intelligence Hub" page.

==================================================
1) CORE GOVERNANCE RULE
==================================================

The following accounts are the ONLY accounts that must have the highest level of permissions in the entire system:

- zalat@nassaqapp.com
- hakim@nassaqapp.com

No other account, under any role, must have the same level of authority.

==================================================
2) SYSTEM-WIDE AUTHORITY
==================================================

These two accounts are the only ones allowed to hold the maximum authority level across the platform.

Their permissions must be treated as:

→ Highest system authority
→ Final administrative control
→ Exclusive super-admin governance

No other account should be able to match, inherit, or simulate these privileges.

==================================================
3) SPECIAL RULES FOR "PRODUCT INTELLIGENCE HUB"
==================================================

Inside the "Product Intelligence Hub" page specifically, only these two accounts:

- zalat@nassaqapp.com
- hakim@nassaqapp.com

must be allowed to perform high-level administrative actions on any challenge card.

These exclusive actions include:

- delete any challenge/card
- edit any challenge/card
- modify any issue status
- change final status
- approve closure
- reopen issue
- assign issue to any team or user
- view the final prompt
- generate the prompt
- regenerate the prompt
- copy the prompt
- trigger Hakim analysis
- access all advanced AI controls
- override workflow actions if needed

==================================================
4) EXCLUSIVE ACCESS RULE
==================================================

No other account in the system must be able to:

- view the final prompt
- copy the prompt
- regenerate the prompt
- delete cards
- apply final approval
- change final statuses
- access super-admin level controls

This restriction applies even if another user has an admin-like role.

==================================================
5) NO EQUIVALENT PERMISSIONS FOR OTHERS
==================================================

There must be NO other account with:

- equal permissions
- similar override powers
- hidden backdoor access
- inherited super-admin capabilities

Even accounts with roles such as:
- Platform Admin
- System Admin
- School Admin
- Product Manager
- Moderator
or any future admin-like roles

must NOT receive these exclusive powers unless the account email is explicitly one of the two approved emails above.

==================================================

Do NOT rely only on frontend visibility.

Backend must strictly validate that only:

- zalat@nassaqapp.com
- hakim@nassaqapp.com

- return a forbidden response

  "error_code": "FORBIDDEN_SUPER_ADMIN_ACTION",
  "message": "This action is restricted to the authorized super-admin accounts only."
}

The system must differentiate between:

A) General administrative roles
B) Exclusive super-admin identity-based permissions

Even if another account has a role label such as "Platform Admin",
that alone must NOT grant these powers.

not by generic role name only.
