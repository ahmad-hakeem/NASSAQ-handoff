# صفحة My Schedule

## الجدول الدراسي للمعلم

## 1. الهدف من الصفحة (Page Objective)

تمكّن هذه الصفحة المعلم من **الاطلاع على الجدول الدراسي الخاص به بشكل كامل ومنظم**، مع توفير رؤية واضحة للحصص اليومية والأسبوعية، وتمكينه من معرفة:

* الحصة الحالية التي يجب عليه تنفيذها الآن.
* الحصة التالية القادمة.
* توزيع حصصه على مدار الأسبوع أو الشهر.
* تفاصيل كل حصة مرتبطة بالفصل والمادة والقاعة.

كما تعتبر هذه الصفحة **نقطة الدخول الأساسية لبدء الحصة الدراسية داخل النظام** حيث يمكن للمعلم الانتقال منها مباشرة إلى **وضع الحصة (Session Mode)** لإدارة الحضور والمشاركة والأنشطة.

---

# 2. مصدر البيانات (Data Source)

تعتمد الصفحة بالكامل على **قاعدة البيانات الخاصة بالجدول المدرسي** والتي يتم إنشاؤها بواسطة:

* **AI Scheduling Engine**
* أو التعديلات اليدوية التي يقوم بها **مدير المدرسة**.

يتم جلب البيانات عبر **API الجدول الدراسي** المرتبط بقاعدة البيانات.

كل حصة يتم عرضها مرتبطة بالكيانات التالية:

* Teacher ID
* Class ID
* Subject ID
* Period ID
* Room ID
* Academic Day

---

# 3. ما تعرضه الصفحة (Displayed Information)

يعرض الجدول جميع الحصص المرتبطة بالمعلم خلال العام الدراسي أو الفصل الدراسي.

لكل حصة تظهر المعلومات التالية:

| الحقل       | الوصف                          |
| ----------- | ------------------------------ |
| اليوم       | اليوم الدراسي (الأحد – الخميس) |
| رقم الحصة   | ترتيب الحصة داخل اليوم         |
| المادة      | المادة التي يدرسها المعلم      |
| الفصل       | الفصل أو الشعبة                |
| توقيت الحصة | وقت البداية ووقت النهاية       |
| القاعة      | رقم القاعة أو المكان (إن وجد)  |
| حالة الحصة  | قادمة / حالية / منتهية         |

---

# 4. طرق عرض الجدول (Schedule View Modes)

يوفر النظام ثلاث طرق لعرض الجدول، ويمكن للمعلم التبديل بينها بسهولة.

## 1) العرض اليومي (Daily View)

يعرض جميع الحصص الخاصة بالمعلم خلال **اليوم الحالي فقط**.

يتم ترتيب الحصص حسب توقيتها من أول اليوم إلى آخره.

يظهر في أعلى الصفحة:

* تاريخ اليوم
* اليوم الدراسي
* مؤشر للحصة الحالية إن وجدت

يُستخدم هذا العرض غالباً أثناء اليوم الدراسي.

---

## 2) العرض الأسبوعي (Weekly View)

يعرض الجدول في شكل **شبكة أسبوعية**.

الأعمدة تمثل:

* أيام الأسبوع الدراسي

الصفوف تمثل:

* أرقام الحصص

كل خلية في الجدول تحتوي على:

* اسم المادة
* اسم الفصل
* توقيت الحصة

هذا العرض يساعد المعلم على فهم توزيع حصصه خلال الأسبوع بالكامل.

---

## 3) العرض الشهري (Monthly View)

يعرض تقويم شهري يوضح:

* الأيام التي يمتلك فيها المعلم حصص
* عدد الحصص في كل يوم

عند الضغط على أي يوم يتم فتح **تفاصيل الحصص لذلك اليوم**.

هذا العرض مفيد للتخطيط طويل المدى.

---

# 5. الوظائف الرئيسية داخل الصفحة (Core Actions)

توفر الصفحة مجموعة من الوظائف التي تساعد المعلم على إدارة يومه الدراسي.

---

## 1) معرفة الحصة الحالية (Current Class Detection)

يقوم النظام تلقائياً بتحديد الحصة الحالية بناءً على:

* الوقت الحالي للنظام
* توقيت الحصص المخزن في قاعدة البيانات

إذا كان الوقت الحالي داخل نطاق توقيت حصة معينة:

يقوم النظام بعرض مؤشر واضح:

**"الحصة الحالية"**

مع إبراز البطاقة الخاصة بالحصة.

---

## 2) معرفة الحصة القادمة (Next Class Detection)

يقوم النظام أيضاً بحساب الحصة التالية القادمة.

ويتم عرض:

* المادة
* الفصل
* وقت البداية

ويظهر تنبيه مثل:

**الحصة القادمة بعد 15 دقيقة**

---

## 3) التنقل بين الأيام (Navigation)

يمكن للمعلم التنقل بسهولة بين الأيام عبر:

* الأسهم التالية / السابقة
* اختيار التاريخ من التقويم
* اختيار اليوم من القائمة

عند تغيير اليوم يقوم النظام:

* بجلب بيانات الحصص لذلك اليوم من قاعدة البيانات
* تحديث العرض فوراً.

---

## 4) فتح تفاصيل الحصة (Class Details)

عند الضغط على أي حصة يتم فتح **نافذة تفاصيل الحصة** والتي تعرض:

* اسم المادة
* اسم الفصل
* عدد الطلاب
* القاعة
* توقيت الحصة
* المعلم المساعد إن وجد
* رابط بدء الحصة

---

## 5) الانتقال إلى وضع الحصة (Start Class / Session Mode)

من داخل تفاصيل الحصة يمكن للمعلم الضغط على زر:

**ابدأ الحصة**

عند الضغط:

يقوم النظام بما يلي:

1. إنشاء Session للحصة.
2. جلب قائمة الطلاب.
3. فتح واجهة إدارة الحصة.

داخل وضع الحصة يمكن للمعلم:

* تسجيل الحضور
* اختيار الطلاب عشوائياً
* تسجيل المشاركة
* تسجيل السلوك
* تقييم المهارات
* تشغيل الأنشطة الصفية

---

# 6. سلوك النظام أثناء عرض الجدول (System Behavior)

يتبع النظام السلوك التالي عند تحميل الصفحة:

### 1) تحميل البيانات

عند فتح الصفحة:

يقوم النظام بتنفيذ:

```
GET /api/teacher/schedule
```

ويتم جلب جميع الحصص الخاصة بالمعلم.

---

### 2) تصفية البيانات

يقوم النظام بتصفية الجدول بناءً على:

* Teacher ID
* Academic Term
* School Calendar

---

### 3) تحديد الحصة الحالية

يقوم النظام بمقارنة:

```
Current Time
VS
Period Start / End
```

لتحديد الحصة الحالية.

---

### 4) تحديث الجدول تلقائياً

يقوم النظام بتحديث حالة الحصص كل دقيقة:

* الحصة القادمة تصبح حالية
* الحصة الحالية تصبح منتهية

بدون الحاجة إلى تحديث الصفحة.

---

### 5) التعامل مع التعديلات على الجدول

إذا قام مدير المدرسة بتعديل الجدول:

يقوم النظام تلقائياً:

* بتحديث بيانات الجدول
* بإظهار التعديل للمعلم فوراً

---

# 7. الحالات الخاصة (Edge Cases)

يتعامل النظام مع الحالات التالية:

### لا يوجد حصص اليوم

يظهر تنبيه:

"لا يوجد حصص لهذا اليوم"

---

### تم تعديل الجدول أثناء اليوم

يظهر إشعار:

"تم تحديث الجدول الدراسي"

---

### تعارض في الجدول

إذا اكتشف النظام وجود تعارض:

يقوم بإرسال تنبيه إلى مدير المدرسة.

---

# 8. تجربة المستخدم (UX Behavior)

يتم تصميم الصفحة بحيث تكون:

* بسيطة
* سريعة
* واضحة بصرياً

مع استخدام:

* ألوان مختلفة للحصص
* مؤشر للحصة الحالية
* بطاقات سهلة القراءة

---

# 9. تكامل الصفحة مع النظام (System Integration)

ترتبط صفحة **My Schedule** بالأنظمة التالية:

* **Scheduling Engine**
* **Session Engine**
* **Attendance Engine**
* **Student Participation Engine**

وهي نقطة البداية لمعظم العمليات اليومية للمعلم داخل النظام.
