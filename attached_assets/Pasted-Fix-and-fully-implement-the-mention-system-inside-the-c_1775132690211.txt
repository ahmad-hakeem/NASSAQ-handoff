Fix and fully implement the @mention system inside the comments section of each Challenge Card in the "Product Intelligence Hub" page.

The current @mention behavior is not working correctly and must be fixed to behave reliably, smoothly, and in full alignment with RBAC / permission rules.

This feature is critical and must work properly in both UI behavior and backend validation.

==================================================
1) CORE REQUIREMENT
==================================================

Inside the comments input field:

- Typing "@" must trigger a mention system
- The mention system must:
  - open a dropdown list of allowed users
  - allow searching by:
    - name
    - email
  - allow keyboard navigation
  - allow selecting a user
  - insert the selected mention properly into the comment input

The mention system must work consistently and correctly in all challenge comment sections.

==================================================
2) INPUT BEHAVIOR
==================================================

- When user types "@":
  → show mention dropdown immediately

- When user continues typing after "@":
  → filter results dynamically in real time

Examples:
- @zah → should search matching users
- @hak → should show hakim@nassaqapp.com if allowed

- When user selects a mention:
  → insert the mention as a styled token/tag inside the comment input
  OR
  → insert it as structured mention text with internal metadata

- Mentioned user must remain clearly distinguishable visually

==================================================
3) REQUIRED MENTION UX
==================================================

The mention dropdown must be:

- fast
- searchable
- keyboard accessible
- clickable
- visually clean
- properly positioned near cursor/input
- scrollable if results are many

Each user result should show:
- display name
- email
- role (if useful)
- optional avatar

The selected mention should appear:
- highlighted
- visually distinct from normal text
- preserved after comment is submitted and displayed

==================================================
4) CRITICAL RBAC / PERMISSION RULES
==================================================

Mention behavior must strictly respect permissions.

The following rules are mandatory:

A) Any Platform Admin account can mention:
- zalat@nassaqapp.com
- hakim@nassaqapp.com

B) The accounts:
- zalat@nassaqapp.com
- hakim@nassaqapp.com

can mention ANY Platform Admin account

C) Mention dropdown must only show users that are allowed by these rules

D) Unauthorized users must NOT appear in mention results

E) If user manually types an unauthorized email or unauthorized @mention:
- backend must reject it
OR
- system must sanitize/block it before submission

==================================================
5) PERMISSION MATRIX
==================================================

Implement mention permissions exactly as follows:

1. Platform Admin accounts:
- can mention:
  - zalat@nassaqapp.com
  - hakim@nassaqapp.com
  - any allowed Platform Admin account according to policy

2. zalat@nassaqapp.com:

3. hakim@nassaqapp.com:

==================================================
6) BACKEND VALIDATION (MANDATORY)
==================================================

Do NOT rely only on frontend UI.

Backend must validate all submitted mentions.

For every submitted comment:
- parse mentions
- validate each mentioned account
- confirm mention permission based on current user role/email
- reject invalid mentions with clear error response

Example error:
{
  "success": false,
  "error_code": "UNAUTHORIZED_MENTION",
  "message": "You are not allowed to mention this user."
}

7) COMMENT STORAGE FORMAT
==================================================

Store comments in a way that preserves mention metadata.

Recommended structure:

{
  "comment_text": "Please review this @Hakim",
  "mentions": [
    {
      "user_id": "123",
      "email": "hakim@nassaqapp.com",
      "display_name": "Ahmed Hakim"
    }
  ]
}

This is required so mentions can:
- render correctly later
- be validated
- be used in notifications in the future
