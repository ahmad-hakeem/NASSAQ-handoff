Implement a strict account identity rule across the entire system to ensure that every user account uses a real personal name instead of a generic account title.

This is a critical UX, governance, and accountability requirement.

==================================================
1) CORE PROBLEM
==================================================

Currently, some accounts use generic names such as:
- Platform Admin
- مدير المنصة
- School Admin
- Teacher
- Student
- Parent
- Website
or any other non-personal/general label

This creates serious problems in:
- accountability
- communication
- comments and mentions
- ownership clarity
- audit clarity
- trust in the system

The system must stop treating generic role names as acceptable account display names.

==================================================
2) CORE RULE
==================================================

Every account in the system must have a real personal display name.

The displayed account name must represent the actual person using the account, not a role title or generic label.

Examples of invalid names:
- Platform Admin
- مدير المنصة
- School Admin
- Teacher
- Student
- Parent
- Admin
- User
- Website
- Test User
- New User
- Manager
- Principal

Examples of valid names:
- Ahmad Zalat
- Ahmed Hakim
- Sarah Ali
- Mohammed Hassan

==================================================
3) REQUIRED SYSTEM BEHAVIOR
==================================================

If any account has a generic/non-personal name, the system must detect it and force the user to update it.

This enforcement must happen consistently across:
- login flow
- dashboard entry
- account settings
- profile page
- all main system pages if needed

==================================================
4) DETECTION LOGIC
==================================================

Create a detection rule that identifies invalid account names.

Detection should include:
- exact generic role names
- common generic account titles
- placeholder names
- suspicious default values
- names identical to role labels
- names that are too vague or non-personal

The system should check:
- Arabic generic labels
- English generic labels
- mixed versions
- uppercase/lowercase variations
- trimmed/spaced variations

Examples to flag:
- Platform Admin
- platform admin
- مدير المنصة
- School Admin
- Teacher
- Parent
- Student
- Website
- User 1
- Test
- Admin123

==================================================
5) FORCED UX ENFORCEMENT
==================================================

If a user account has an invalid generic name:

Show a persistent, highly visible, annoying warning/notice until the user changes it.

This warning must:
- remain visible across the system
- not disappear permanently until the name is corrected
- be difficult to ignore
- clearly explain why the change is required

Examples:
- top sticky banner
- blocking modal
- repeated alert card
- header notification
- profile completion warning

Recommended behavior:
A) Show a persistent top warning banner on every page
B) Show a forced modal after login if name is invalid
C) Keep reminder visible in account settings until fixed

==================================================
6) WARNING MESSAGE CONTENT
==================================================

The warning message should be direct and clear.

Examples:
Arabic:
"يجب تحديث اسم الحساب ليكون اسمك الشخصي الحقيقي بدلًا من اسم عام مثل مدير المنصة أو Platform Admin. هذا مطلوب لتحسين الوضوح والمساءلة داخل النظام."

English:
"You must update your account name to your real personal name instead of a generic label such as Platform Admin or School Admin. This is required for accountability and clarity across the system."

Add CTA button:
- "Update My Name"
- "تحديث اسمي الآن"

==================================================
7) FORCED ACTION FLOW
==================================================

When invalid name is detected:

1. User logs in
2. System checks display name
3. If invalid:
   - show warning banner
   - show forced modal or profile completion prompt
   - direct user to account settings or inline edit form
4. User updates personal name
5. Save new name
6. Revalidate
7. Remove warning only after valid personal name is saved successfully

==================================================
8) VALIDATION RULES FOR PERSONAL NAME
==================================================

Personal name validation should be stricter than current behavior.

Rules:
- must not be empty
- must not match blocked generic names
- must be at least 2 meaningful words if possible
- must contain alphabetic characters
- must not be only numbers
- must not be role-based titles only
- must not be placeholder text

Optional stronger validation:
- minimum length
- reject repeated characters
- reject “test”, “demo”, “user”, “admin”, etc.

Examples of acceptable formats:
- Ahmad Zalat
- Ahmed Hakim
- Sara Mohamed
- أحمد زلط
- أحمد حكيم

==================================================
9) ACCOUNT SETTINGS UX
==================================================

In account settings, make the name update process extremely easy.

Requirements:
- place name field prominently
- show inline validation
- explain why real name is required
- show invalid examples vs valid examples
- save instantly or via clear save button
- after success, update UI immediately everywhere

Also:
- reflect new name in:
  - header
  - comments
  - mentions
  - challenge reporter name
  - activity logs
  - notifications
  - issue details
  - dashboard references

==================================================
10) GLOBAL SYSTEM IMPACT
==================================================

Once updated, the real personal name must appear consistently across the entire system wherever the account is referenced, including:

- profile/header
- comments
- mentions
- challenge reporter
- created by
- activity timeline
- audit logs
- assignments
- dashboard contributor analytics

No part of the UI should continue displaying the old generic label after update.

==================================================
11) DATABASE / BACKEND REQUIREMENTS
==================================================

Implement backend support for this rule.

Requirements:
- validate display name on save
- store a flag such as:
  "has_valid_personal_name": true/false
- detect legacy invalid accounts
- allow system-wide enforcement without relying only on frontend

Optional useful fields:
- display_name
- role
- has_valid_personal_name
- name_last_updated_at

==================================================
12) LEGACY DATA CLEANUP STRATEGY
==================================================

The system must identify all existing accounts with generic names and mark them as requiring correction.

Create a rule that applies to:
- old accounts
- newly created accounts
- imported accounts
- seeded accounts

Any account with invalid name must enter the forced correction flow.

==================================================
13) NEW ACCOUNT CREATION RULE
==================================================

For all future account creation flows:

Do NOT allow default generic display names such as:
- Platform Admin
- School Admin
- Teacher
- Parent
- Student
- Website

Instead:
- require real personal name during account creation
OR
- force completion on first login before using the system

==================================================
14) UX PRIORITY / SEVERITY
==================================================

This warning should feel intentionally persistent and impossible to forget.

However:
- do not make the UI broken
- do not block essential emergency actions unless required
- maintain professional tone
- make it clear that the correction is mandatory

Preferred severity model:
- Strong persistent warning
- Forced modal on first login
- Sticky banner until resolved
- Optional restriction on some advanced actions until corrected

==================================================
15) OPTIONAL ENFORCEMENT IMPROVEMENT
==================================================

Optional enhancement:
If the user ignores the warning for too long, restrict certain actions until the name is corrected.

Examples:
- cannot create new challenge
- cannot comment
- cannot assign
- cannot use mentions

Only allow:
- account settings access
- essential navigation
- save name

This is optional but recommended if governance must be strict.

==================================================
16) ANALYTICS / ADMIN OVERSIGHT
==================================================

Add admin visibility for invalid generic accounts.

Platform Admin should be able to see:
- accounts still using generic names
- correction status
- date last reminded
- whether account is compliant or not

Optional dashboard widget:
- Accounts requiring personal name update

==================================================
17) DESIGN / UI REQUIREMENTS
==================================================

The warning UI must be:
- highly visible
- professional
- persistent
- hard to ignore
- clear in Arabic and English
- consistent with the system design

Possible UI patterns:
- sticky top alert
- profile completion card
- blocking modal
- account settings warning state

Use:
- warning color styling
- clear CTA button
- concise explanation
- no ambiguity

==================================================
18) FINAL GOAL
==================================================

Ensure that all system accounts display real personal names, not generic role labels.

This should permanently improve:
- accountability
- collaboration
- clarity in comments and mentions
- reporter identity
- audit quality
- overall professionalism of the system

This must be implemented as a permanent system rule, not a temporary reminder.
