Hakim Context Engine
### Intelligent Character Behavior System for NASSAQ
Create a system called **Hakim Context Engine** responsible for controlling the appearance, pose selection, and interaction behavior of the AI assistant **Hakim** across the NASSAQ platform.
Hakim must behave like an **intelligent contextual assistant**, not a static image.
The engine should determine:
• when Hakim appears
• which pose to use
• which message to display
• which animation level to trigger
based on **system events, page context, and user actions**.
---
# 1️⃣ Engine Objective
Hakim Context Engine transforms Hakim into a **dynamic AI assistant layer** inside the platform.
The engine must ensure that:
• Hakim reacts to user actions
• Hakim reacts to system states
• Hakim reacts to AI insights
• Hakim reacts to success or problems
This creates the feeling that **an intelligent system is working behind the interface.**
---
# 2️⃣ Core Engine Architecture
The Hakim Context Engine consists of the following components:
### 1️⃣ Context Detector
Detects the current state of the system.
Inputs include:
page_type
user_role
system_event
workflow_state
ai_analysis_state
task_status
Example contexts:
Landing Page
First Login
Teacher Dashboard
Student Dashboard
AI Insights
Schedule Creation
Attendance Recording
System Alert
Task Completed
---
### 2️⃣ Pose Selector
Selects the most appropriate Hakim pose.
Uses rules:
```
context → pose group → random variation
```
Example:
context = schedule_created
possible poses:
Positive feedback pose
Motivating pose
Congratulating student pose
Engine randomly selects one.
---
### 3️⃣ Message Generator
Generates the contextual message displayed with Hakim.
Message types:
welcome
guidance
explanation
analysis
alert
motivation
success
Example:
pose = AI thinking pose
message:
"دعني أفكر قليلاً… أقوم بتحليل البيانات."
---
### 4️⃣ Animation Controller
Controls Hakim animation level.
Three levels must exist.
---
# 3️⃣ Hakim Animation Levels
### Level 1 — Idle Animation
Used when Hakim is simply present.
Very subtle movement.
Examples:
• slow breathing
• gentle floating
• blinking
• minimal head movement
Purpose:
Make Hakim feel alive without distracting the user.
---
### Level 2 — Interaction Animation
Triggered when the user interacts.
Examples:
• pointing
• explaining gesture
• guiding hand movement
Used during:
instructions
help
explanations
alerts
---
### Level 3 — Celebration Animation
Triggered when something positive happens.
Examples:
• clapping
• happy movement
• congratulation gesture
Used after:
task completion
student success
goal achievement
---

# 6️⃣ Randomized Pose Selection
For natural behavior, the engine must allow **pose rotation**.
Example:
```
context: task_completed
poses:
Positive feedback pose
Motivating pose
Congratulating student pose
engine randomly selects one.
```
This prevents the interface from feeling repetitive.
