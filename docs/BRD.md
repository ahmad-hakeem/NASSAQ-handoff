# وثيقة متطلبات العمل (BRD) — منصة نَسَّق NASSAQ

**الإصدار:** 1.0 &nbsp;|&nbsp; **التاريخ:** 2026-08-02 &nbsp;|&nbsp; **الحالة:** معتمدة من الواقع الفعلي للنظام (وثيقة توصيفية للنظام كما هو مبني)

---

## 1. الملخص التنفيذي

**نَسَّق (NASSAQ)** منصة سحابية شاملة متعددة المستأجرين (Multi-Tenant) لإدارة المدارس، موجهة للسوق العربي (عربية أولاً مع دعم الإنجليزية)، تغطي الإدارة المدرسية والشؤون الأكاديمية وأداء الطلاب، مدعومة بميزات ذكاء اصطناعي (المساعد "حكيم"). تخدم المنصة:

- **المدارس الحقيقية**: قيادة مدرسية (مدير، إداري، إداري مساعد)، معلمون، أولياء أمور.
- **المعلم المستقل (Independent Teacher)**: مساحة عمل خاصة تعمل كمدرسة مصغّرة مستقلة.
- **إدارة المنصة**: مدير المنصة، مدير العمليات، مسؤول أمن، محلل بيانات.

**الرابط الإنتاجي:** يُنشر التطبيق على Replit (Autoscale) مع نطاق مخصص، والواجهة والخلفية تُخدمان من نفس الأصل.

---

## 2. الأهداف والنطاق

### 2.1 أهداف العمل
1. رقمنة العمليات المدرسية اليومية (الجداول، الحضور، الدرجات، السلوك، الواجبات، التواصل) في نظام واحد.
2. تمكين القيادة المدرسية من رؤية تشغيلية وتحليلية فورية.
3. إشراك أولياء الأمور عبر بوابة مخصصة بمعلومات أبنائهم.
4. تمكين المعلم المستقل من إدارة طلابه بمعزل تام عن المدارس.
5. توظيف الذكاء الاصطناعي (حكيم) في الرؤى والتخطيط والتنبيه المبكر للطلاب المعرضين للخطر.
6. عزل بيانات كل مدرسة عزلاً صارماً مع أعلى معايير الأمان والامتثال (متوافق مع توجهات نظام حماية البيانات الشخصية PDPL).

### 2.2 داخل النطاق
جميع الوحدات الوظيفية المفصلة في القسم 4، لكل الأدوار في القسم 3.

### 2.3 خارج النطاق (حالياً)
- **بوابة الطالب**: الكود موجود (لوحة، جدول، درجات، حضور، ملف شخصي، تقدّم، إنجازات) لكن دخول الطلاب **معطّل على مستوى المنصة** — كل مسارات `/student/*` تعيد التوجيه لتسجيل الدخول.
- صفحة التقييمات القديمة للقيادة المدرسية (مخفية للصيانة).
- طلب اجتماع ولي الأمر (موجود لكنه مخفي من الواجهة).

## 3. الأدوار والصلاحيات (RBAC)

| الدور | الرمز | الوصف والصلاحيات |
|---|---|---|
| مدير المنصة | `platform_admin` | صلاحية كاملة: المدارس، المستخدمون، القواعد، المراقبة، التكاملات، مركز الأمان، السجلات، الاتصالات، الحذف النهائي لمساحات العمل المؤرشفة |
| مدير عمليات المنصة | `platform_operations_manager` | لوحة المنصة ومركز المنتج فقط |
| مدير منصة مساعد | `platform_sub_admin` | قراءة فقط: لوحة المنصة، قوائم المدارس والمستخدمين |
| مسؤول أمن المنصة | `platform_security_officer` | سجلات التدقيق فقط |
| محلل بيانات المنصة | `platform_data_analyst` | سجلات التدقيق فقط |
| مدير المدرسة | `school_principal` | كل صفحات القيادة المدرسية + إعدادات المدرسة |
| إداري المدرسة | `school_admin` | نفس صلاحيات المدير التشغيلية + الإعدادات |
| إداري مساعد | `school_sub_admin` | الصفحات التشغيلية للقيادة بدون إعدادات المدرسة؛ الصلاحيات الأساسية مخصصة له يدوياً (لا حزمة افتراضية) |
| معلم مدرسة | `teacher` | مساحة عمل المعلم (حصص، حضور، درجات، سلوك، واجبات، ملف إنجاز) |
| معلم مستقل | `independent_teacher` | مساحة عمل المعلم + إدارة مساحة عمل خاصة (استيراد بيانات، أولياء أمور، مواد، تقويم، دورة حياة كاملة) |
| ولي أمر | `parent` | بوابة أولياء الأمور (متابعة الأبناء والتواصل) |
| طالب | `student` | معطّل حالياً على مستوى المنصة |

**قواعد عامة:**
- مساحة الأسماء القياسية للقيادة المدرسية هي `/principal`؛ و`/school` و`/admin` أسماء بديلة تُطبَّع تلقائياً.
- الأدوار الثلاثة للقيادة المدرسية تُعامل جميعها كـ"مدير مدرسة" في التوجيه والواجهة.
- بعض الصفحات تُحكم إضافياً بصلاحيات دقيقة (مثل `ai.lesson_plans` لمخطط الدروس، وصلاحيات الاستيراد والتحليلات لمساحة عمل المعلم المستقل).
- تبديل الأدوار متاح للمشرفين (مع معاينة الدور الفعّال).

## 4. المتطلبات الوظيفية (الوحدات)

### 4.1 المصادقة وإدارة الحسابات
- تسجيل دخول بريد/كلمة مرور مع JWT (رموز وصول وتحديث، إبطال جلسات، تغيير كلمة مرور إجباري).
- **مصادقة ثنائية (MFA)**: مفاتيح مرور WebAuthn أو TOTP مع رموز استرداد لمرة واحدة؛ تصعيد تحقق (Step-Up) للعمليات الحساسة؛ رموز تحقق بالبريد.
- التسجيل الذاتي للمعلمين وموافقات طلبات التسجيل، ودعوات أولياء الأمور والمتعاونين عبر روابط موقّعة.
- فرض الأسماء الحقيقية على الملفات الشخصية (تحقق خادمي).
- مفتاح إيقاف طارئ لفرض MFA على مستوى المنصة (متغير بيئة).

### 4.2 إدارة المنصة (Platform Administration)
- لوحة قيادة مركزية بإحصاءات المنصة، إدارة المدارس/المستأجرين وتفاصيلها، إدارة مستخدمي المنصة.
- إدارة القواعد، مراقبة صحة النظام، التكاملات، مركز الأمان، عارض سجلات التدقيق.
- مركز اتصالات المنصة (إشعارات وتعميمات).
- **مركز المنتج (Product Hub)**: تقديم ومناقشة ومتابعة قضايا/اقتراحات المنتج (متاح للإدارة والقيادة المدرسية والمعلمين)، مع مولّد موجّهات تنفيذ متوافق مع أدوات البناء.
- حذف نهائي خاضع للرقابة لمساحات العمل المؤرشفة (خارج نطاق واجهة المعلم المستقل نهائياً).

### 4.3 إدارة المدرسة (القيادة المدرسية)
- **لوحة المدرسة**: نظرة تشغيلية شاملة مع بطاقات مؤشرات ورؤى حكيم داخل المحتوى.
- **المستخدمون والمعلمون**: إدارة المعلمين والموظفين (سجل المعلم موجود في جدولي `users` و`teachers` ويُوفَّق بينهما)، إسناد المعلمين للفصول والمواد.
- **الطلاب**: دليل الطلاب، ملف الطالب الشامل (حضور، درجات، سلوك، مهارات، صحة — مع إخفاء الحقول الحساسة عن المعلمين)، معالج إنشاء طالب.
- **الفصول**: إدارة الفصول بسعة قصوى (افتراضي 30)، نظام مراحل/صفوف قانوني موحّد (3 مراحل / 12 صفاً).
- **المواد**: جدول `subjects` هو المصدر القانوني للمناهج والإسناد والجدولة، مع حصص أسبوعية لكل مادة.
- **الحضور**: حضور الطلاب وحضور المعلمين، مع أعذار الغياب وسير عمل الموافقة عليها وإمكانية التراجع.
- **الهيكل الأكاديمي**: أعوام وفصول دراسية، مراحل وصفوف، قاعات، فترات زمنية (أجراس).

### 4.4 الجدولة الذكية (Smart Timetabling)
- **توليد آلي للجدول** بمحرك قيود (قيود صلبة وناعمة: تعارضات المعلم/الفصل/القاعة، الحصص الأسبوعية للمواد، توزيعات...) مع تفسير أسباب التعذّر.
- التوليد يعمل **كمهمة خلفية** (استجابة 202 + استعلام حالة) في مجمع معالجة مستقل حتى لا يجمّد الخادم؛ تشغيل واحد لكل مدرسة.
- **شبكة جدول رئيسية** بسحب وإفلات، مسودة قابلة للتحرير مستنسخة من المنشور، نشر ببوابات تحقق (Publish Gates)، وإلغاء نشر.
- **حصص الانتظار (Standby)**: احتساب أهلية المعلمين للانتظار من الجدول الفعلي، وإسناد بدلاء للمعلمين الغائبين مع إشعار وتوثيق من قام بالإسناد.
- جاهزية الجدول (فحوص اكتمال المدخلات قبل التوليد).

### 4.5 مساحة عمل المعلم (معلم المدرسة)
- **لوحة المعلم** وجدوله الشخصي (تسميات الحصص من الترتيب المنطقي بعد استبعاد الفسح).
- **الحصة المباشرة (Live Session)**: بدء حصة وإدارتها لحظياً — تسجيل مشاركة وتقييم وتلاوة وسلوك ومهارات لكل طالب، عدّاد تقييم، مكافأة تميّز للإجابات المتتالية، تراجع عن آخر إجراء، حفظ تلقائي كل 10 ثوانٍ، إنهاء الحصة باعتماد الدرجات، وإغلاق تلقائي للحصص المهجورة نهاية اليوم الدراسي.
- **كشف المتابعة**: شبكة درجات لكل فصل بأعمدة قابلة للتخصيص (درجة/تحقق/نص)، مزامنة ثنائية الاتجاه مع سجلات الحصص، حفظ متسلسل يمنع فقدان التعديلات.
- **الحضور، التقييمات والدرجات، السلوك، الواجبات** (نموذجان للواجب: واجب الحصة والواجب الرقمي بمهام وتسليمات).
- **خطة المنهج**: خاصة بكل معلم/فصل/مادة؛ القيادة تنشئ خططاً عامة للفصل.
- **مخطط الدروس بالذكاء الاصطناعي** (بصلاحية `ai.lesson_plans`).
- **ملف الإنجاز (Portfolio)**: شواهد وسيرة مهنية (دورات، جوائز، خطابات شكر) بمرفقات تُخزَّن في مخزن ملفات منفصل وتُجلب عند الطلب، مع تصدير.
- مركز تواصل المعلم وإشعاراته.

### 4.6 مساحة عمل المعلم المستقل (Independent Teacher)
- كل ميزات معلم المدرسة، إضافة إلى:
- **مستأجر اصطناعي خاص** (`itw_{user_id}`) بعزل كامل؛ أي وصول بمعرّف عبر مساحات العمل يعيد 404 (لا يؤكد وجود بيانات الغير).
- معالج تهيئة أول دخول، إدارة مواد خاصة، استيراد جماعي للطلاب والفصول، تقويم شخصي، إعدادات عام/فصل دراسي نشط.
- **دليل أولياء الأمور** ودعوات ربطهم بالطلاب.
- **التدريس المشترك (Co-Teaching)**: دعوة معلم مستقل آخر للتعاون على فصل واحد محدد (المسار الوحيد المسموح به عبر المستأجرين)، بدورة حياة: معلّق → مقبول → ملغى/منتهٍ، ودعوات JWT صالحة 7 أيام مجزأة التخزين.
- **دورة حياة مساحة العمل**: تصدير (ZIP موقّع صالح 24 ساعة، لمرة واحدة، بيانات الاعتماد الحساسة محجوبة، يتطلب MFA) → حذف ناعم (يشترط تصديراً خلال 24 ساعة + تأكيد الاسم + MFA) → إعادة تفعيل خلال 30 يوماً → حذف نهائي بيد مدير المنصة فقط.
- كل عمليات الكتابة/التصدير الحساسة تتطلب تصعيد MFA حديثاً (مغلف 403 قياسي تعيد الواجهة تشغيله بعد التحقق).
- سجل نشاط مساحة العمل (تدقيق ذاتي).

### 4.7 بوابة أولياء الأمور
- لوحة بنظرة عامة على الأبناء وآخر المستجدات، ومركز موحّد للطفل (تفاصيل، جدول، سلوك، واجبات، تقارير وإحصاءات).
- جدول الطفل (يدعم مدارس المعلم المستقل أيضاً)، درجات، حضور، سلوك، والواجبات بنوعيها (واجب الحصة + الواجبات الرقمية).
- تقرير ملخص الحصة يصل لولي الأمر، أعذار الغياب من مركز التواصل، رسائل مباشرة، تحليلات الطالب.
- إعدادات ووثائق قانونية وإشعارات، ومساعد حكيم مخصص مدرك للأبناء.

### 4.8 الذكاء الاصطناعي — حكيم (Hakim)
- **مساعد محادثة عام** مثبّت مرة واحدة على مستوى التطبيق لكل الأدوار المؤهلة (نسخة مدركة للأبناء لولي الأمر)، بروابط داخلية مُتحقَّق منها حسب الدور.
- **رؤى وتحليلات**: نظرة عامة، تنبيهات، توقعات، توصيات، الطلاب المعرضون للخطر (رادار مخاطر بدلالات موحّدة)، تدخلات.
- **خطط علاجية وإثرائية** للطلاب (توليد، سجل، تصدير DOCX/PDF) بصلاحيات لكل نوع خطة، وختم مستندات.
- مخطط دروس ذكي.
- **ضوابط**: بوابة موافقة (Consent) لاستخدام الذكاء الاصطناعي، تجهيل أسماء، مهلات محدودة ومنفّذ مخصص لاستدعاءات المزود، حدود معدل خاصة للواجهات العامة، ميزانية استدلال مناسبة لنموذج الاستدلال.

### 4.9 الاتصالات والإشعارات
- إشعارات لحظية عبر WebSocket (`/ws/notifications`) + جرس إشعارات في الشريط الجانبي لكل الصفحات.
- محرك إشعارات مراعٍ لتفضيلات المستخدم (داخل التطبيق + بريد)، تعميمات مدرسية، مركز تواصل موحّد للقيادة ومركز لكل دور.
- بريد إلكتروني للعمليات (إعادة تعيين كلمة مرور، OTP، دعوات، دورة حياة مساحة العمل) بروابط عامة مبنية من عنوان التطبيق الإنتاجي حصراً.
- تطبيع قيم الإشعارات القديمة عبر مطبّعات مشتركة.

### 4.10 التقارير والتصدير والاستيراد
- تقارير تشغيلية وأكاديمية بفلاتر، تصدير PDF/CSV/XLSX (دعم عربي كامل في PDF).
- **حماية من حقن الصيغ**: تحييد الخلايا التي تبدأ بـ `=`/`+`/`-`/`@` وتعطيل تحويل الصيغ والروابط تلقائياً في كل مصدّر.
- أسماء ملفات عربية في الترويسات عبر ترميز `filename*=UTF-8`.
- **استيراد نور (Noor)**: استيراد طلاب بمسودات ومعاينة واعتماد، مع دلالات استرجاع للسجلات المحذوفة ناعماً، وإعادة حل الفصول عند الاعتماد، وفرض سعة الفصول (تفاعلي: 409، جماعي: بلا فصل + تحذير).
- استيراد/تصدير جماعي للمعلمين والطلاب، والمناهج الرسمية كبيانات مرجعية للعرض.
- سجل الطلاب (تجميع درجات وسطي عند القراءة).

### 4.11 محرك الموافقات الموحّد
- محرك عام لأنواع الطلبات (أعذار الغياب، طلبات التسجيل...) بدورة حالة معرفة، تحقق من الانتقالات، وسجل أحداث تدقيقي.

### 4.12 التدقيق (Audit)
- سجل تدقيق غير قابل للتعديل للعمليات المهمة (MFA، الدخول، دورات الحياة، التعاون، الموافقات...)، تُخزَّن الرموز خاماً وتُعرَّب في الواجهة؛ هدف الاحتفاظ: سنتان متاحة + 5 سنوات أرشيف بارد.

## 5. نموذج البيانات (أهم الكيانات)

**أشخاص وهوية:** `users`، `teachers`، `students`، `parents`، `guardian_links` (العلاقة والبريد القانونيان لربط ولي الأمر)، `user_sessions`، `revoked_tokens`، عائلة جداول `mfa_*`.

**بنية أكاديمية:** `schools` (المستأجر؛ يميّز المدرسة الحقيقية عن مساحة المعلم المستقل عبر نوع المستأجر)، `academic_years`، `academic_terms`، `educational_stages`، `grade_levels`، `classes`، `subjects`، `physical_classrooms`، `time_slots`.

**إسناد وجدولة:** `teacher_assignments` (القانوني)، `teacher_class_assignments`، `timetables`، `timetable_sessions`، `schedule_sessions`، `timetable_constraints`، `timetable_runs` (مهام التوليد)، `substitute_assignments`.

**عمليات يومية:** `attendance`، `class_sessions` (الحصص المباشرة)، `session_interactions`، `session_homework`، `session_notes`، `followup_records`، `grade_columns`، `student_grades`، `assessments`، `assessment_submissions`، `behaviour_records`، `behaviour_types`، `student_skills`.

**تواصل وسير عمل:** `notifications`، `notifications_preferences`، `messages`، `approval_requests`، `approval_events`، `events`، `calendar_events`، `audit_logs`.

**ذكاء اصطناعي ومحتوى:** `hakim_insights`، `ai_insights`، `ai_interventions`، `lesson_plans`، `teacher_portfolio_meta`، `portfolio_evidence`، `portfolio_files` (مخزن مرفقات مرجعي العدّ).

**مساحة المعلم المستقل:** `workspace_collaborators`، `workspace_quota`، `parent_invitations`، `noor_import_history`، `noor_import_drafts`.

**بنية تحتية:** `generic_documents` (مخزن مستندات JSONB عام لعدة مجموعات)، `rate_limit_counters`، `public_hakim_rate_counters`.

## 6. المتطلبات غير الوظيفية

### 6.1 الأمان
- JWT موقّع بمدد صلاحية وإبطال؛ تجزئة كلمات المرور bcrypt؛ رسائل خطأ عربية آمنة لا تكشف تفاصيل داخلية.
- MFA (WebAuthn/TOTP + رموز استرداد) مع تصعيد تحقق للعمليات الحساسة.
- **عزل المستأجرين**: كل استعلام حساس مقيد بـ `school_id/tenant_id` على مستوى قاعدة البيانات؛ قراءات by-id عبر المستأجرين تعيد 404؛ الاستثناء الوحيد المسموح: فصل التدريس المشترك المسمى.
- تحديد معدل موزّع عبر Postgres (متسق عبر كل نسخ Autoscale)، بحدود لكل مسار وطريقة.
- ترويسات أمان وCSP، حماية تصدير من حقن الصيغ، تحقق خادمي من الأسماء، إخفاء بيانات الطلاب الحساسة عن الأدوار غير المخوّلة.
- فحوص أمنية في CI: pip-audit وsafety وBandit (الحرجة تمنع الدمج) + اختبارات عزل مستأجرين.

### 6.2 الأداء وقابلية التوسع
- نشر Autoscale عديم الحالة؛ لا حالة في الذاكرة (الجلسات والحدود والمهام كلها في قاعدة البيانات).
- **لا عمل معالجة مكثف على حلقة الأحداث**: كل توليد PDF/XLSX/ZIP يمر عبر مجمع خيوط محدود (`cpu_offload`)، وتوليد الجداول في مجمع منفصل وكمهمة خلفية قابلة للاستعلام.
- قراءات قاعدة البيانات محدودة السقف افتراضياً مع بث Keyset للعمليات الشاملة.
- المرفقات الكبيرة خارج مستندات القراءة الساخنة (نمط مخزن ملفات + جلب عند الطلب).
- مسابر صحة: `/healthz` (حيوية) و`/readyz` (جاهزية بمهلة، تتجاوز وسيط الجلسات).

### 6.3 سلامة البيانات والنشر
- المخطط يُدار حصراً عبر Alembic؛ العمليات التدميرية والبذر محظورة خارج التطوير؛ بوابة إقلاع ترفض التشغيل الإنتاجي إذا لم يكن المخطط عند الرأس.
- حارس هجرات تدميرية + فحص انحراف المخطط + نسخ احتياطية قبل العمليات الخطرة وتمارين استرجاع دورية.
- بيانات الإنتاج لا تُفقد أو تُستبدل أثناء النشر إطلاقاً.

### 6.4 التعريب والواجهة
- عربية أولاً بواجهة RTL كاملة (خصائص منطقية `ps/pe/ms/me`)، مرآة إنجليزية، تواريخ هجرية عبر أداة تحويل مخصصة.
- نظام تصميم موحّد (`design_guidelines.json`): ألوان علامة (كحلي/تركوازي/بنفسجي للذكاء الاصطناعي)، أيقونات lucide فقط، كل التحذيرات عبر `NassaqAlertDialog`.
- استجابة كاملة للجوال (نمط تركيب مزدوج للجداول).

### 6.5 الموثوقية والمراقبة
- Sentry للأخطاء، سجلات وصول منظّمة JSON بمعرّف طلب، مقاييس مجمعات المعالجة تحت `/system/metrics`.
- إغلاق تلقائي للحصص المهجورة، حاصدات للمهام القديمة، تنظيف عدّادات الحدود المنتهية.

## 8. ضمان الجودة

- **بوابات CI إلزامية** على كل PR ودفع إلى main: خلفية (قاعدة بيانات نظيفة + هجرات + pytest كامل ~2,367 اختباراً)، واجهة (Jest)، E2E (Playwright)، أمان (فحوص اعتماديات + Bandit + اختبارات أمنية).
- بوابات محلية مطابقة عبر `scripts/ci/run_gate_local.sh`.
- حراس انحدار مخصصون: عمل الحلقة، عقود المسابر، الهجرات التدميرية، عزل المستأجرين، حقن الصيغ.
- حسابات اختبار للأدوار في `TEST_CREDENTIALS.md` لفحص التدفقات يدوياً.
- **فجوات معروفة**: لا بوابة فحص أنواع (mypy/tsc)؛ تغطية E2E خمسة ملفات أساسية؛ Bandit يمنع الحرجة فقط.

## 9. القيود والافتراضات

1. دخول الطلاب معطّل منصةً حتى قرار منتج لاحق.
2. Autoscale يفرض انعدام الحالة: لا ملفات محلية دائمة ولا ذاكرة مشتركة بين الطلبات.
3. اللغة الأساسية للواجهة والرسائل هي العربية؛ رسائل الأخطاء للمستخدم عربية دائماً.
4. التقويم الهجري عبر مكتبة التحويل المخصصة فقط.
5. المستأجر هو حدود البيانات المطلقة؛ أي ميزة عابرة للمستأجرين تتطلب مساراً معتمداً صراحة (الوحيد حالياً: التدريس المشترك).
6. موافقة (Consent) مطلوبة قبل تمرير بيانات الطلاب لميزات الذكاء الاصطناعي، مع تجهيل الأسماء.
